# AGENTS.md — AndroidAPS (MDI fork)

Guidance for AI coding agents working in this repo. Read this before exploring — it distills verified knowledge about the codebase, the fork's MDI features, and lessons learned the hard way.

## What this repo is

- **Personal MDI fork** of [nightscout/AndroidAPS](https://github.com/nightscout/AndroidAPS) (based on upstream `master`), now **4.0.0**. Target audience: pen/MDI users running the app with the **virtual pump** ("MDI" pump type) in open loop. See `README.md` for the full feature list and the safety warning.
- **Orient yourself with the fork diff:** `origin` is the personal forge, `upstream` is nightscout, and the local `upstream_master` branch is the last upstream merge point. After the 4.0.0 merge, use the backup tag `backup/pre-4.0.0-merge` and `git diff backup/pre-4.0.0-merge..HEAD` to see the fork surface. The old `git diff upstream_master..HEAD` is no longer the fork surface.
- **4.0.0 architecture (read before touching paths below):**
  - KMP modules keep shared code in `src/commonMain/kotlin`; Android-only code is `src/androidMain` and tests are `src/androidHostTest` / `src/commonTest`. The Android app/plugin modules still use `src/main`/`src/test`, and the app also has `src/testFull` and `src/androidTestPumps`.
  - The phone UI is **Jetpack Compose** in `:ui` (`ui/src/commonMain/.../compose`), not XML DialogFragments. `appshell` owns navigation. New UI screens are `*Screen.kt` + ViewModel + `*UiState.kt`.
  - DI is **Metro** (`@Inject`, `@ContributesBinding`, `@ContributesIntoMap`, `@ViewModelKey`), not Dagger. `CoreObjectsGraph` provides the wizard cycle.
  - Notifications are `NotificationId` + `NotificationManager` (no `Notification` + `RxBus` events). Preference keys live in `core/keys/.../commonMain` and are rendered from `PreferenceSubScreenDef`; settings are searchable through `ui/search/BuiltInSearchables.kt`.
  - The bolus path is `MasterActionExecutor` / `BatchExecutor` / `WizardExecutor`; MDI forces `recordOnly = true` at that layer and in `executeBolus`. `CommandQueueImplementation.bolus()` no longer has an MDI branch.
  - The wizard has `CarbsType` (BREAD/CAKE/PIZZA) auto e-carbs. Deferred carbs force BREAD and carb time 0; the two must never run together.
  - Key MDI port locations: `core/objects/src/commonMain/.../MdiApsProfile.kt`, `core/interfaces/src/commonMain/.../pump/{BasalInjection,InjectionPosition}.kt`, `core/interfaces/src/commonMain/.../utils/ApsResults.kt`, `core/objects/src/commonMain/.../wizard/PendingCarb*.kt`, `plugins/aps/src/commonMain/.../loop/LoopPlugin.kt`, `plugins/constraints/src/commonMain/.../safety/SafetyPlugin.kt`, `implementation/src/commonMain/.../alerts/LocalAlertUtilsImpl.kt`, Compose `ui/src/commonMain/.../compose/{wizardDialog,insulinDialog,carbsDialog,overview,profileManagement}/`.
  - Tests: per-module `:module:testAndroidHostTest`; flavoured app `:app:testFullDebugUnitTest`; pure KMP `:module:jvmTest`. Compile checks: `:app:compileFullDebugKotlin` and `:module:compileAndroidMain`. `:core:keys` is KMP with a JVM target: `:core:keys:compileKotlinJvm`.
- **This is safety-critical insulin-dosing software.** Keep diffs minimal, prefer additive changes, and never relax caps/safety logic beyond what is explicitly documented.
- **Rebase discipline:** fork changes are kept as additive as possible so rebases onto upstream stay clean. Avoid reformatting upstream code. Don't rename/move upstream symbols without a strong reason.

## Build & test

- Gradle **9.8.2**, **Java 21** (`Versions.jvmTarget = JVM_21`), Kotlin, AGP; `compileSdk 37`, `minSdk 31`. Version constants in `buildSrc/src/main/kotlin/Versions.kt`.
- **Flavors** (dimension `standard` in `app/build.gradle.kts`): `full`, `pumpcontrol`, `aapsclient`, `aapsclient2`, `aapsclient3`. KMP library modules have no flavor; compile them with `:module:compileAndroidMain` (e.g. `./gradlew :ui:compileAndroidMain`).
  - App: `./gradlew :app:compileFullDebugKotlin` (4.0 task), `./gradlew :app:assembleFullRelease`.
  - `:core:keys` is KMP with a JVM target → `./gradlew :core:keys:compileKotlinJvm`.
- **Full build:** `./gradlew :app:assembleFullRelease` (or Android Studio).
- **Unit tests:** `./gradlew testFullDebugUnitTest testDebugUnitTest allTests` is what 4.0 CI runs (`runtests.sh`). Per module: `./gradlew :core:objects:testAndroidHostTest` / `:plugins:aps:testAndroidHostTest` / `:module:jvmTest`. Single class: `./gradlew :plugins:aps:testAndroidHostTest --tests "app.aaps.plugins.aps.loop.LoopPluginTest"`; reports under `<module>/build/test-results|reports/tests/testAndroidHostTest`.
- **Parity tests** (Kotlin APS ↔ JS reference): `app/src/androidTest/kotlin/app/aaps/ReplayApsResultsTest.kt` — needs a device/emulator; run when touching determine-basal logic.
- **Cross-module breakage:** compiling one module in debug does NOT catch breakage in pump plugins (e.g. Java callers of core interfaces). When changing core interfaces, verify `./gradlew :app:compileFullReleaseKotlin`.
- **Toolchain:** always `./gradlew` — the wrapper pins Gradle **9.8.2** while a system `gradle` is 8.x. Java 21 required (`.envrc`/Nix `devenv` provides JDK 21 + Kotlin; `local.properties` points at the Android SDK). DI is Metro (KSP-generated); if a stale KSP/Metro cache produces a spurious graph error, remove the module's `build/generated/ksp`, `build/tmp/kspCaches` and `build/kotlin/kspCaches` and rebuild (and avoid parallel Gradle runs).
- No ktlint/format gate is wired into this build. Follow the surrounding style (4-space indent, standard Kotlin) and don't reformat upstream code; the goal is keeping rebases small.
- Layout/resource-only changes don't need a build — validate with the editor's error check.
- **This checkout carries stale generated output under `*/build/`** (hundreds of MB, incl. old `strings.xml` copies and test reports). Exclude it when searching (`--glob '!**/build/**'`) — a hit there is never the source file to edit.

## Architecture essentials

- **Runtime APS = Kotlin ports** (`plugins/aps/.../DetermineBasalSMB|AMA|AutoISF.kt`). The `determine-basal.js` under `app/src/androidTest/assets` is a **parity-test fixture only** — "determine-basal.js line N" in discussions is conceptual.
- **Data flow:** source plugins → `workflow` calculation pipeline (bucketed data → IOB/COB/autosens) → APS plugin (`DetermineBasal*`) → `LoopPlugin` → enactment via `CommandQueue` → pump, or notifications (open loop).
- **UI is Compose** (see the 4.0 section above). The shared dialog fields (notes, injection position, date/time, OK/Cancel) are Compose components; position/notes visibility is read from `OverviewShowNotesInDialogs` / `OverviewShowPositionInDialogs` in the dialogs.
- **DI is Metro** (see above).
- **Record-only (MDI) delivery:** carbs never go to the pump; MDI forces `recordOnly` in `MasterActionExecutorImpl.prepareBatch`/`executeBolus` and the wear/quick-wizard paths. The old `CommandQueueImplementation.bolus()` MDI branch is gone. `DetailedBolusInfo.createBolus(iCfg)` now requires the insulin config.
- **eCarbs:** a `CA` row with `duration > 0` and/or future timestamp; `AppRepository` expands it into 15-min slices feeding COB. One record = linear absorption; multi-bump curves need multiple records.
- **`Pump.isMDI()`** (`core/interfaces/pump/Pump.kt`, `model() == PumpType.MDI`) is the gate for MDI-specific behavior. **Do NOT use `is VirtualPump`** for feature gating — it also matches virtual-pump users emulating real pumps. Generic "no physical pump" checks (BT permissions, pump sync verification) legitimately use `is VirtualPump`. `model()` is only valid after `refreshConfiguration()` (runs in `onStart`). MDI is not a plugin of its own: it is `pump:virtual` with `StringKey.VirtualPumpType` = `"MDI"`, which `VirtualPumpPlugin.refreshConfiguration()` maps to `PumpType.MDI`.

## Hard-won lessons (repeat offenders)

- **`rh.gs(id, args)` swallows formatting errors** (falls back silently, logs to Crashlytics). A placeholder/arg mismatch won't crash — it renders wrong. Always count `%n$` placeholders vs args at the call site. And `R.string.x` from the **wrong module compiles fine but resolves the wrong resource** — check which module's `strings.xml` you added the string to.
- **Negating a compound visibility expression flips upstream behaviour for everyone else.** `batteryLayout.visibility = (isMDI || (!isPatchPump || useHardwareLink)).not()` looked like "hide in MDI" but is the exact negation of the upstream rule for every non-MDI pump (Combo/Dana lost the battery light, Omnipod Dash/Eros gained an empty row) — and virtual-pump users emulating a real pump are a supported configuration. Write `!isMDI && <upstream expression>` and delete the now-dead upstream assignment instead of shadowing it.
- **Preference `dialogMessage`/`setMessage` strings are never run through `String.format`.** A `%%` in such a string renders literally (`10%%`); the escape is only correct in strings passed to `rh.gs(id, args)`. Also check placeholder counts, not just escapes, when a string is reused for both.
- **Strings:** English only (Crowdin handles translations). Prefer new short strings over editing long ones shared with AAPSClient (they're translated). Log-only format strings can be `translatable="false"`.
- **Kotlin interface default params are invisible to Java callers** (`@JvmOverloads` is illegal on interface methods). Adding a defaulted param to a core interface breaks Java call sites (e.g. Omnipod Eros). Keep the default and update Java call sites explicitly.
- **`dateUtil.computeDiff` decomposes** the duration — DAYS/HOURS/MINUTES are separate components and every map lookup is nullable. Reading only HOURS+MINUTES wraps at 24 h. Fold days in: `hours = (diff[DAYS] ?: 0L) * 24 + (diff[HOURS] ?: 0L)` (see `StatusViewModel.formatAge`).
- **`firstOrNull { predicate }` + nullable mapper** silently falls back to the first non-match. Use `firstNotNullOfOrNull { mapper }`; for the element itself: `firstNotNullOfOrNull { el -> mapper(el)?.let { el } }`.
- **`ReactiveVisibilityContext` (core:ui `PreferenceState.kt`) wraps `VisibilityContext` for reactive dependencies — every property must be delegated.** It forgot `isMdi`, so it fell back to the interface default `false` and **every `ElementVisibility.MDI_ONLY` preference was hidden** in the Compose settings (hypo treatment carbs, deferred carbs, insulinReq median, position in dialogs) even on an MDI master. `ReactiveVisibilityContextTest` guards the flag. When adding a property to `VisibilityContext`, delegate it there too.
- **Hidden prefs can be load-bearing.** MDI hides several APS prefs, but the caps were still read into `OapsProfile` — override values at the point of use (`MdiApsProfile`), never mutate stored prefs. Same for the wizard's partial-bolus `OverviewBolusPercentage`: it is hidden in MDI, and *every* reader (dialog, `QuickWizardEntry`, Wear prefill) must substitute 100 there.
- **`Constraint.setIfSmaller(limit, reason)` adds the reason whenever `limit < originalValue`, even if it does NOT clamp** (it only clamps when `limit < currentValue`). So `SafetyPlugin` prints "Limiting max basal rate to 500 U/h because of pump limit" *alongside* a 2 U/h hard-limit clamp. Don't assert on reason lists without accounting for this — and don't assume a listed limit was the binding one.
- **`?: 0.0` as a "missing limit" fallback is a trap — it means "limit to 0", not "no limit".** `SafetyPlugin.applyBasalConstraints` had `tbrSettings()?.maxDose ?: 0.0`; nulling MDI's `tbrSettings` would have zeroed the pen suggestion (`tempExtraUnits = (rate − basal) × 0.5`). Use `?.let { }` so absence means unlimited. Same trap exists in `APSResultObject` (androidTest) — harmless there because zero-temp returns earlier.
- **Pen-suggestion sizing must never come from a U/h quantity.** It originally used `(result.rate − basal) × 0.5`, which equals `insulinReq` by construction (`rate = basal + 2*insulinReq` in the engines) — but `result.rate` there is the *constrained* rate, clamped by `applyBasalConstraints` to `min(max(ApsMaxBasal, maxDailyBasal), 4×basal, 3×basal)`. With the `ApsMaxBasal` default of **1.0 U/h** and a flat profile that fallback tops out at **1/3 U** — below the 0.5 U pen step, so it floors to 0 and can never size a suggestion on its own. Size from `insulinReq` instead.
- **`result.smb > 0` is a trap as a "should we bolus" gate.** `rT.units` (→ `smb`) is assigned in exactly one place — inside `if (microBolusAllowed && enableSMB)` — and `microBolusAllowed = isSMBModeEnabled()` chains to `SafetyPlugin.isClosedLoopAllowed()`. That constraint means "*may* closed loop run" (dev build, active EB, MDI) — **not** "is the running mode open loop"; the OPEN_LOOP running mode only selects the notification branch. Until `isClosedLoopAllowed()` started refusing MDI, SMB mode stayed enabled and the engine emitted real `smb` values in open loop (computed, never enacted) — that is what fed the original pen-suggestion notifications, the feature was never dead. Since the MDI refusal, `smb` is *always* 0 in MDI, so an `if (result.smb > 0)` gate is dead code **today** — which is exactly why the suggestion now sizes from `insulinReq` unconditionally.
- **`isChangeRequested()` is not an MDI gate.** In open loop it returns true for any requested temp basal/SMB, including the temp-basal request the engine computes before constraints in MDI. The Loop action sheet (`LoopActionViewModel`) therefore offered "Accept new temp basal" on a pen setup; it and `MainViewModel.performLoopAccept` now check `isMDI()`. MDI only uses the pen-notification path, and `PEN_BOLUS_SUGGESTION` is deliberately allowed through the Android “urgent alarms” notification switch because it is an advisory suggestion, not an alarm.
- **`predictedLow` is the only low guard the pen path has.** The engine's `if (enableSMB && minGuardBG < threshold) enableSMB = false` never runs in MDI (reason above). `RT`/`APSResult` now carry `predictedLow`, set unconditionally in `DetermineBasalSMB`/`DetermineBasalAutoISF` (`minGuardBG < threshold`) and `DetermineBasalAMA` (`minPredBG < threshold`); `presentPenBolusSuggestion` dismisses on it. Note AMA computed `insulinReq` locally and never exposed it — it does now (`rT.insulinReq`).
- **`TestBaseWithProfile` formats `rh.gs(id, args)` as `String.format(rh.gs(id), arg)`.** So a 2-arg `gs` call NPEs ("String.length() because s is null") unless you also stub the **1-arg** `gs(id)` with the format template — e.g. `whenever(rh.gs(R.string.bolus_suggestion_text)).thenReturn("Bolus %1\$s U now")`. This is also why reason strings appear fully formatted in test assertions.
- **`determineCorrectBasalSize`/`determineCorrectExtendedBolusSize` throw `IllegalStateException` on null settings** (`PumpTypeExtension.kt`) — now null-safe, but anything consuming `tbrSettings()`/`extendedBolusSettings()` must handle absence.
- **In unit tests a `PumpDescription()` behaves like `resetSettings()` values (`isTempBasalCapable=true`, `tempBasalStyle=PERCENT`), not the field initialisers.** Consequence: the ABSOLUTE pump-limit block is skipped while the PERCENT one runs — that's why `SafetyPluginTest.basalRateShouldBeLimited` sees only the hard-limit reason but `percentBasalRateShouldBeLimited` also sees the `500.00 U/h … pump limit` reason. Set `isTempBasalCapable = false` explicitly to exercise the MDI path.
- **`BaseSeries.getHighestValueY()` returns 100d for an empty series** (not 0) — guard div-by-zero accordingly. Never make `HeartRateDataPoint`/`StepsDataPoint` scale-aware: series are built once but shared across secondary graphs, and per-graph scale multipliers make them vanish.
- **`PendingCarbStore` claim protocol:** `beginCommit()` → `PendingCarbClaim(token)` → `commitSucceeded(token)`/`commitFailed(token)`. Both calls are **no-ops for a superseded token** (claim taken over after the 60 s timeout, or the entry cancelled/overwritten meanwhile) so a late Rx callback cannot clear the new claim — `commitSucceeded` returns false there. The persisted copy is removed when the claim is taken (at-least-once). Release the claim **as soon as the carbs are persisted** (and in a `catch` around everything between the claim and the write) — a claim that is never released makes "Eat now" silently dead while the entry stays on screen, and the retry would duplicate the carbs. Side effects that can throw belong after the release, wrapped.
- **Deferred carbs + pump delivery:** the pending entry must only be created once the injection was logged (MDI: insert callback, pump: `commandQueue.bolus` success callback). Creating it on dispatch offers "Eat now" for a bolus that never happened.
- **Missed-Lantus reminder state lives in prefs, not memory.** `LocalAlertLongKey.NextMissedLantusReminderAlarm` throttles re-raises and must be reset to `0` whenever the reminder is dismissed/disabled — a stale future value keeps it suppressed. `lastLantusInjection()` only searches `MdiMissedLantusLookbackDays` (min **2 days**). "No dose found" ⇒ dismiss **only when no cycle is active** (`NextMissedLantusReminderAlarm == 0`); once a cycle is running the dose merely aged out, so it keeps nagging — shrinking the lookback below the user's injection interval must not silently switch the reminder off.
- **Injection position:** the dialog shows the previous site as a disabled field, but the persisted note format **must stay `"pos x"`** — `InjectionPosition.POSITION_REGEX` parses it. Never change `appendToNotes`/`stripPosition`.
- **Preferences are declarative `PreferenceSubScreenDef`s.** A key whose `visibility`/`dependency` evaluates false silently disappears from every screen and from search; nested subscreens are rendered from the same definition, so there is no `addPreferenceScreen` whitelist to update anymore.
- **XML style:** roughly match upstream (attribute-per-line is the local convention) so diffs stay small for rebases — that's the whole point. Don't reformat upstream code, but don't turn formatting into a chore either.
- **Comments: keep only critical rationale.** Prefer self-explanatory code and short one-line KDoc on public/interface API. Avoid narrating obvious branches, restating the code/KDoc on overrides, or adding long "what it does" paragraphs. A comment earns its place only when it explains a non-obvious *why* (safety invariant, surprising workaround, hidden constraint) — and comments added during a change should be trimmed before finishing.
- **Editing large files:** the `edit` tool needs a unique `oldString` — widen the context or use `replaceAll` for repeated blocks, and note that two identical blocks each needing the same edit must be sequential calls (the second only becomes unique after the first is disambiguated). Big multi-edit rewrites on one file can land conflicting intermediate states — split them and re-read after a failure. `git mv` with long paths can fail oddly in fish — use `bash -c` with absolute paths.
- **Tests:** `InjectionPositionTest` guards the PRIMING/NOTE filters. `LoopPluginTest` covers `penBolusSuggestion` math. `DetermineBasalSmbMdiTest` covers the fixed-basal split. Pure math belongs in testable companion functions/data classes.
- **A new `RT` field that gates a UI feature must be initialised in *every* engine.** `RT.insulinReq` was only set in AMA's `eventualBG >= max_bg` branch, so in-range AMA runs produced `null`; `ApsResults.medianInsulinReq` drops nulls, which made a stale high value from the last 15 min win the median while the current run said "in range". SMB/AutoISF initialise it to `0.0` in the `RT(...)` — do the same.
- **A hidden control must never have an effect.** `CarbsDialog` hid the TT checkboxes for MDI but its BG<72 auto-check re-ticked the hidden hypo box, and `submit()` read it — a hidden checkbox created (and cancelled) temp targets. Gate the auto-check **and** the `submit()` read on `!isMDI`, for every TT checkbox (`hypo`/`activity`/`eatingSoon`), same for `InsulinDialog.startEatingSoonTt`.
- **`TestBaseWithProfile` stubs `gs(id, arg)` with a real `String.format` answer.** Re-stubbing one specific string must use `doReturn("…").whenever(rh).gs(...)` — a plain `whenever(rh.gs(...))` first executes the old answer and NPEs.
- **`DetermineBasalSMB`/`AutoISF` reuse one mutable `consoleLog`/`consoleError` list across runs** — a second `determine_basal` call overwrites the first RT's log. Snapshot `rt.consoleLog` per run before invoking again in tests.
- **Threshold comparisons: OR/AND inversion traps.** "Rewrite when diff > 1 U OR diff > 10 %" inverts to tolerance `min(...)` for the no-rewrite check — `max(...)` silently requires exceeding BOTH and kills one rule for doses below the crossover. The Lantus rewrite shipped with `max` and 8→9 U (12.5 %) slipped through. Lesson: derive the no-trigger condition algebraically, don't eyeball it; when the spec is "any change", just use `!=` instead of a tolerance band at all.
- **MDI wizard path:** when `pump.isMDI()`, `BolusWizard.commonProcessing` persists carbs/bolus directly (`persistenceLayer`) instead of `commandQueue.bolus()`; the eCarbs path in `BolusWizard.scheduleECarbs` has the same MDI branch (`Action.EXTENDED_CARBS`). Any new feature that schedules eCarbs must mirror it. Superbolus is skipped in MDI; "record only" is forced in `TreatmentDialog`.
- **`BolusWizard.doCalc` percentage wiring:** `totalPercentage` is only consumed when `usePercentage` is true — the unchecked path uses the positional `percentageCorrection` param. New default-path percentage logic must go through a dedicated path, not `totalPercentage`.
- **The hidden partial-bolus pref is guarded by the callers, not by `doCalc`.** `doCalc` now applies whatever percentage it is given (an MDI-wide "force 100" also discarded the *explicit* percentages of the wizard `%` checkbox, `QuickWizardEntry` per-button % and the watch wizard). Every place that reads `OverviewBolusPercentage` (hidden in MDI) must return 100 for `isMDI()`: `WizardDialog.defaultBolusPercentage()`, `QuickWizardEntry.defaultBolusPercentage()`, and the Wear prefill in `DataHandlerMobile` (~`EventData.Preferences`). In `usePercentage` mode `doCalc` reports the applied % through `calculatedPercentage`/`percentageCorrection`, and `WizardDialog` re-seeds the `%` field from it — otherwise toggling the `%` checkbox changes the dose (units→% silently dropped the typed correction). The control also recalculates on toggle for the same reason.
- **Pen-suggestion notification settings (Oct 2026):** master `MdiBolusSuggestionEnabled`, min `MdiMinBolusSuggestion`, smoothing `MdiBolusSuggestionSmoothing` + `MdiBolusSuggestionMedianMinutes`. Traps: `invoke()` persists the APS result **before** `presentPenBolusSuggestion` — the median lookup must drop the persisted twin (handled in `ApsResults.recent()`, `core:interfaces` `utils` — shared with the MDI status card's insulinReq light, keep it the single copy); a smoothed median ≤ 0 must force `fullInsulinReq = 0.0`, **not** null (null falls back to the `smb + tempExtraUnits` legacy path); the smoothed value must also pass `applyBolusConstraints` (SafetyMaxBolus); min compares against the **pen-step-rounded** suggestion, `coerceIn(bolusStep, maxSuggestion)`; all the pen-suggestion prefs hang off the master `MdiBolusSuggestionEnabled` (not `smbEnabled` — `rT.insulinReq` is set outside the SMB gates, `DetermineBasalSMB` ~line 1063); `MdiMaxBolusSuggestion` has `dependency = MdiBolusSuggestionEnabled`; `MdiBolusSuggestionMedianMinutes` depends only on `MdiBolusSuggestionSmoothing` — declarative dependency visibility is not transitive, so it is not additionally gated by the master switch.
- **Pen-suggestion sizing:** full `insulinReq` (not `insulinReq/2`), `DoubleKey.MdiMaxBolusSuggestion` cap (default 4 U), 0.5 U pen-step floor (round **down**), 60-min throttle from the last *shown* suggestion. (`BooleanKey.MdiFullInsulinReqSuggestion` was removed Sep 2026.) `ApsMaxSmbFrequency` does **not** suppress suggestions — it only zeroes `result.smb`, which sizing ignores; post-bolus suppression is soft (recent bolus → IOB up → `insulinReq` down) + the throttle. The pref is hidden in MDI (`OpenAPSSMBPlugin`/`OpenAPSAutoISFPlugin` pref screens). `Max IOB` is the cumulative safety bound. Note the suggestion also passes `applyBolusConstraints` → `SafetyMaxBolus` (default **3 U**) + hard limit. The pen-step floor is applied to the raw `insulinReq` (and to the smoothed median) **before** the constraints: `applyBolusConstraints` rounds to the *nearest* step, so flooring afterwards turns a 0.80 U need into a 1.0 U suggestion and a 0.26 U need into 0.5 U.
- **Nightscout v3 derives the treatment `identifier` itself: `uuid5("NightscoutRocks!", "<device>_<date>_<eventType>")`** (`cgm-remote-monitor` `lib/api3/shared/operationTools.js`; AAPS sends no `device` for treatments, so the key starts with `undefined_`). Two treatments written in the same millisecond with the same event type are therefore the **same document** to NS, and the second POST is a **replace** (200 `isDeduplication`), not an error. A meal wizard logs the bolus and its carbs from the same `now`: the bolus uploads first, the carbs overwrite it, and the insulin silently vanishes from Nightscout while AAPS's own IOB still counts it (prove a missing dose from NS `devicestatus` IOB against the ICfg curve). `CA.toNSCarbs()` uses "Meal Bolus" only for ≥ 12 g, so small carbs escape by accident. `DetailedBolusInfo.createCarbs()` nudges the carbs 1 ms off the bolus timestamp on collision — keep that, and keep the `insulin != 0.0` guard (a carbs-only entry must keep its exact time; deferred carbs are committed later anyway). Guarded by `DetailedBolusInfoTimestampTest`. A failed upload is invisible in NS: `dbOperationTreatments` logs a 4xx as `FAIL` but returns `true`, so the sync pointer advances and the record is never retried.
- **`Profile.getIc()` routes through dynamic-IC APS plugins** (`aps.supportsDynamicIc()`). For the *profile's* configured I:C use `getIcTimeFromMidnight(secondsFromMidnight)` — same block math, no dynamic override. Also: `OKDialog.show` has a `Spanned` overload — colored dialog text (`ForegroundColorSpan` + `rh.gac(context, R.attr...)`) needs no custom dialog layout.

## Working checklist for a change

1. Locate the feature in the **fork feature map** above; read the related memory-style notes in `AGENTS.md` before coding.
2. Make the smallest additive change; follow existing patterns (`isMDI()` gating, `persistenceLayer` persistence, keys in `core:keys`). Settings surfaces are `PreferenceSubScreenDef`/`BuiltInSearchables` (built-ins) or a plugin's `getPreferenceScreenContent()`; keys are auto-registered, local export follows the key's `exportable` flag, openHumans needs the `AllowedPreferenceKeys` allow-list.
3. New user-visible text → `strings.xml` of the **owning module**; new prefs → `core/keys` with `min`/`max`/`unitType` in the key constructor (and `visibility`/`dependency` where needed).
4. Compile-check the right task: `:module:compileAndroidMain` for KMP libraries, `:app:compileFullDebugKotlin` for the app; for core-interface changes run `:app:compileFullReleaseKotlin`.
5. Add/extend unit tests for pure math; run the affected module's `testAndroidHostTest` (app: `testFullDebugUnitTest`).
6. Validate XML with the editor's error check; keep diffs to upstream files purely additive. If the change alters a fork-visible feature or uncovers a repeat trap, update `README.md` and this file.
